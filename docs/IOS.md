# Building Wayamesh for iOS

**Status: nothing in this repository has been built or run on iOS.** This was prepared on Linux. `npx expo export --platform ios`
(a JavaScript bundle) is the only iOS check that has been run. Treat every iOS behaviour below as untested.

## What is different on iOS

* **No Bluetooth receiving.** The Kotlin module `modules/wayamesh-ble` is Android-only (`expo-module.config.json` lists only
  `android`). On iOS `requireOptionalNativeModule` returns null, `isPeripheralSupported()` is false, and the Mesh tab says
  "Bluetooth hand-off is Android-only; use QR or text". All BLE imports are guarded; the central half uses `react-native-ble-plx`,
  which is a separate native module and is unverified on iOS.
* Payments and messages hand over by QR, copy/share text, or the internet (relays, settlement). Chat works over relays.
* `NSBluetoothAlwaysUsageDescription`, `NSCameraUsageDescription`, `NSFaceIDUsageDescription` are in `app.json`
  (`ios.infoPlist`), plus `expo-camera`, `expo-local-authentication`, `expo-secure-store` and `react-native-ble-plx` plugins.
* The wallet key is stored with `expo-secure-store`; with biometric unlock on, reads require Face ID / Touch ID. Face ID makes the
  app briefly `inactive`, so chat locks only when the app goes to `background`.

## The committed `ios/` folder is stale

`ios/` is an old prebuild: project `wayameshtmp`, bundle id `org.name.wayameshtmp`, no usage strings. It does not match `app.json`
(`com.wayamesh.mobile`). If EAS finds it, EAS treats the project as bare and ignores `app.json`. To avoid that, a `.easignore`
(copy of `.gitignore` plus `/ios`) keeps `ios/` out of EAS uploads so EAS runs `expo prebuild` for iOS from `app.json`.
The lead should consider `git rm -r ios` (it is regenerated by `npx expo prebuild -p ios`) and then remove the `/ios` line from
`.easignore`. Android keeps using the committed `android/` folder (version bumped there too).

## Build with EAS (needs an Apple Developer account, USD 99 per year)

1. `npm i -g eas-cli && eas login` (account `tevinprime66`, project id is in `app.json`).
2. `eas credentials -p ios` (or let the first build prompt): EAS creates the distribution certificate and provisioning profile.
3. Internal test build for registered devices (ad hoc): `eas device:create`, register each tester's iPhone, then
   `eas build -p ios --profile preview`. Install from the link EAS prints.
4. Simulator build (no Apple account needed for the build itself, runs on a Mac only): `eas build -p ios --profile preview-ios-simulator`.
5. TestFlight: `eas build -p ios --profile production` then `eas submit -p ios --latest`. In App Store Connect create the app with
   bundle id `com.wayamesh.mobile`, add testers under TestFlight, answer the export-compliance question (the app sets
   `ITSAppUsesNonExemptEncryption=false`; confirm this is correct for your use of encryption before shipping).
6. Version: `app.json` `version` and `ios.buildNumber`. Increase `buildNumber` for every upload.

## Not verified

Everything on a device: install, launch, camera QR scan, Face ID prompt and key retrieval, secure-store behaviour after a
restore, relay WebSockets in the background (they stop when the app is backgrounded by design), BLE central, App Store review.
Apple may question Bluetooth and encryption declarations. Arc is testnet only; do not ship to the public App Store with real money.
